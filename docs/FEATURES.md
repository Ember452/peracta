## 1. 核心承诺

Peracta 对使用者的承诺有四条，前三条是功能，第四条是品格：

| # | 承诺 | 含义 |
|---|---|---|
| **0** | **只声明观测到的事实** | 不声称未观测的事；缺失证据显式标注，不编造健康分、不编造成功率 |
| 1 | **已完成的步骤不重跑** | 崩溃恢复后，走完的步骤直接复用结果 |
| 2 | **已提交的副作用不重复发生** | 退款/下单/发信/扣款等不可逆动作，恰好一次 |
| 3 | **任何一次运行可确定性重放** | 同一份日志，在本地逐字节复现当时的执行路径 |

第 0 条放在最前面，因为它决定其余三条**怎么被证明**：不是"我们保证"，而是"这是我们观测到的"。

## 2. 功能全景

### A. 执行内核

| ID | 功能 | 说明 |
|---|---|---|
| A1 | 工作流定义 | `@flow` + `ctx.step()`；顺序、分支、并行、子工作流 |
| A2 | 事件日志 | append-only 事件流 + checkpoint 快照；崩溃后从最近快照 + 日志尾部续跑 |
| A3 | 确定性重放 | 录制全部非确定性来源：模型输出、时间、随机数、UUID、并发完成顺序；重放时从录制读取，出现未录制来源即报错并定位 |
| A4 | 持久化定时器与信号 | `ctx.sleep(1, days=1)`；`ctx.signal("approval", timeout="3d")` 等人工审批，进程可随时退出 |
| A5 | 崩溃恢复 | `kill -9`、OOM、机器重启后自动/手动续跑；已完成的 step 不重跑 |
| A6 | 工作流版本迁移 | 跑了三天的任务遇到新代码；版本标记 + 安全点升级 + 不兼容变更检测 |
| A7 | 租约与 fencing token | 多 worker 下的执行者唯一性、防脑裂、假死检测与抢占重派 |
| A8 | 背压与流控 | 提交速率超消费能力时整流；队列长度与排队延迟的自适应控制 |

### B. 副作用安全（exactly-once）

| ID | 功能 | 说明 |
|---|---|---|
| B1 | 声明式副作用 | `ctx.effect(key=...)`；幂等键的**规范化**（参数序列化、语义等价、时间戳/UUID 等非确定性参数处理） |
| B2 | 预占（claim-before-execute） | 动手之前先落凭据；状态机 `claimed → executing → committed / failed / unknown` |
| B3 | 结果缓存与复用 | 重复调用直接返回上次结果，不再碰外部系统 |
| B4 | 未知态对账 | `reconcile=上游查询函数`：崩溃在"已发出未确认"窗口时，查上游确认；查不到 → 人工仲裁队列，不猜 |
| B5 | 补偿事务（Saga） | 注册补偿动作，失败逆序回滚；补偿本身也幂等；补偿失败进人工队列 |
| B6 | 不可补偿操作分类 | 明确标注"发了的邮件收不回来"，这类只能靠预占防重 |
| B7 | 账本后端可插拔 | 内存（测试）/ SQLite（单机）/ Postgres（生产）/ Redis（低延迟）/ 独立账本服务（高吞吐） |
| B8 | 账本性能 | group commit（把 N 次 fsync 合并）、热点键分片、原子 claim-if-absent |

### C. 可观测与取证

| ID | 功能 | 说明 |
|---|---|---|
| C1 | 运行时间线 | 工具调用 / claim 状态迁移 / 重试 / 补偿 / 对账，放在同一条时间线上 |
| C2 | 可靠性回执 | 每次运行输出：哪几步复用了录制、哪几步跳过了已提交副作用、哪几步真正重放 —— 可指回日志记录 |
| C3 | 未确认态面板 | unknown 列表 + 一键对账 |
| C4 | 指标与追踪 | 成功率、重复拦截次数、对账队列深度、补偿失败数；OpenTelemetry 接入 |
| C5 | 证据导出 | JSON / HTML / Markdown，供 CI 与第三方工具消费 |

### D. 正确性验证（差异化核心）

| ID | 功能 | 说明 |
|---|---|---|
| D1 | 故障注入矩阵 | `kill -9`、超时、重复投递、乱序、部分成功、时钟跳变、租约过期、磁盘满 |
| D2 | 注入点控制 | 第 N 步前/后/之中、按概率、按持续时间 |
| D3 | 边界覆盖分析 | 哪些 step 从未被任何故障命中 = 测试盲区（直接回答"你的边界只是猜测"） |
| D4 | 重复执行检测 | 对比正常与恢复后的实际副作用序列；估算**重复代价**（多花了多少钱、影响多少用户） |
| D5 | 静态扫描 | 找出未保护的副作用调用；跨过程调用链分析（`@tool` 入口 → helper → 真实写操作） |
| D6 | 一致性检查器 | 从账本历史验证"恰好一次"，而不是靠"没观察到问题" |
| D7 | CI 集成 | PR 上跑抽样故障矩阵；`--fail-on duplicate_effect` 直接拦合并 |
| D8 | 可复现报告 | 记录随机种子、注入点、结果；任何人可复现同一实验 |
| D9 | 反例强制 | 验证器必须配一个**故意坏掉**的样例，证明它真的会发现重复副作用 |

### E. 接入与分发（阶梯式）

设计意图：**每一级都能单独用、单独出价值，接入成本从 0 递增。**

| ID | 形态 | 接入成本 | 用户拿到什么 |
|---|---|---|---|
| E1 | `peracta scan` | 零接入 | 扫完就告诉你哪几处调用崩溃后会重复执行 |
| E2 | `@effect` 保护库 | 改一行 | 副作用恰好一次 |
| E3 | `peracta verify` | 一条命令 | 故障注入报告，证明保护有效 |
| E4 | `peracta run` | 用它写工作流 | 断点续跑、确定性重放、定时器、信号、版本迁移 |
| E5 | 框架适配器 | 装中间件 | LangGraph（middleware）、crewAI（tool 装饰器）、OpenAI Agents SDK、自研循环 |
| E6 | SDK | — | Python 优先；未来 JS/TS（npm 名已留空位） |
| E7 | 宿主内形态 | 一句话 | MCP server / Skill，在 Claude Code、Qoder 等宿主里直接调用 |

### F. 运行与治理（远期）

| ID | 功能 | 说明 |
|---|---|---|
| F1 | 多租户配额与调度 | 加权公平队列（WFQ），防大租户饿死小租户 |
| F2 | 优先级与抢占 | 长任务公平性 |
| F3 | 沙箱化工具执行 | cgroup 配额、seccomp 限制、namespace 隔离、网络出口白名单、审计 |
| F4 | 服务端 | 任务查询、团队视图、趋势；上传管道多级脱敏 + 幂等上报 |
| F5 | 多种运行模式 | 本地 CLI / 常驻 daemon（cron、CI 无人值守） |
| F6 | 跨语言数据面 | 写入路径瓶颈时抽出独立账本服务（Java + Netty + group commit） |

### G. 人机协作

| ID | 功能 | 说明 |
|---|---|---|
| G1 | 人工审批 | signal + 超时策略；审批可能挂几小时到几天 |
| G2 | 人工仲裁队列 | 未知态、补偿失败需要人判断时排队，不静默吞掉 |
| G3 | 修复建议 | 白名单目标 + dry-run 先行 + apply 需显式确认 + 内容哈希快照可回滚 |

## 3. 两条贯穿全局的设计哲学

1. **证据边界**：只声明观测到的。缺失证据显式标注，不把"未知"粉饰成"通过"。
   —— 这条直接决定了 D9（反例强制）和 C2（可靠性回执）的存在。
2. **零依赖、可嵌入、本地优先**：核心不引入运行时依赖；单文件 SQLite 起步；原始数据不出机器。
   —— 这让"装得上、审得过、敢放进生产代码库"成为可能。

## 4. 典型使用场景

| 场景 | 痛点 | Peracta 的作用 |
|---|---|---|
| 客服退款/理赔 Agent | 崩溃重跑 → 重复退款、重复发信；还有"不知道退没退"的工单 | 预占防重 + 未确认态对账 |
| 长跑研究 Agent（几十分钟、几十次调用） | 第 38 步被杀掉，重跑一遍重烧一遍钱 | 断点续跑 + 确定性重放 |
| 代码/工具执行类 Agent | 外部世界有真实副作用 | 沙箱隔离 + 副作用边界声明 |
| Agent 平台方 | 多团队共用，互相拖垮 | 多租户配额与公平调度 |
| CI/CD | 新人把 `effect` 改成裸调用 | 静态扫描 + 故障矩阵门禁 |

## 5. 定位与竞品关系（简表）

| | Temporal / Restate | LangGraph / crewAI | actenon-scan | **Peracta** |
|---|---|---|---|---|
| 已完成步骤不重跑 | ✅ | 部分 | — | ✅ |
| 副作用恰好一次 | 需自行实现 | ❌（issue 在等） | — | ✅ |
| 确定性重放整次运行 | 仅 workflow code | ❌ | — | ✅ |
| 故障注入证明"没重复" | ❌ | ❌ | 静态扫描 | ✅ |
| 零运行时依赖 | ❌ | ❌ | ✅ | ✅ |

一句话定位：**别人给你"不会重跑"，Peracta 给你"证明没有重复产生副作用"。**

## 6. 长期非目标（每阶段重申）

- ❌ 通用 LLM tracing / token 成本大盘（红海）
- ❌ Agent 框架本身：不做 prompt 编排、不做多智能体角色模板
- ❌ 模型能力评测榜单
- ❌ BPM / 低代码流程编辑器
- ❌ LLM 网关（不代理、不路由模型请求）
- ❌ 为"多 Agent"而多 Agent 的模板化设计
