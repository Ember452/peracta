## 1. 一句话

> **给 AI Agent 的持久化执行内核：已完成之事，不可重做。**
> 每一步都留下凭据 —— 崩溃后从断点续跑，副作用恰好一次，任何一次运行都能逐字节重放。

中文名：**毕录**（毕 = 完成，录 = 记录）。英文名 `peracta`（拉丁语：per + acta，"已完成之事"）。

## 2. 锁定的范围

### 2.1 V0.1 做什么（单机内核 + 一条验证命令）

| # | 能力 | 形态 |
|---|---|---|
| 1 | 工作流定义 | `@flow` + `ctx.step()`，同步 API |
| 2 | 持久化 | 事件日志落在本地 SQLite 单文件 |
| 3 | 断点续跑 | `peracta resume <run-id>`：已完成步骤不重跑 |
| 4 | 副作用幂等 | `ctx.effect(key=...)`：先留凭据再执行，重复调用返回上次结果 |
| 5 | 未知态处理 | `ctx.effect(..., reconcile=...)`：崩溃后查上游确认，查不到进人工队列 |
| 6 | 确定性重放 | `peracta replay <run-id>`：从日志复现整次运行 |
| 7 | 故障注入验证 | `peracta verify --fault crash --at every-step --repeat N`：报告哪一步会重复执行 |

### 2.2 V0.1 明确不做

- ❌ 分布式：多 worker、租约、fencing token、脑裂处理
- ❌ 多租户调度、配额、背压、优先级
- ❌ 沙箱执行（代码隔离、资源限额、网络白名单）
- ❌ 任何 LLM 集成 —— 模型调用只是 `step` 的一种，内核不该知道 LLM 存在
- ❌ Web 控制台、HTML 报告（V0.1 只出终端 + JSON）
- ❌ 框架适配器（LangGraph / crewAI / OpenAI Agents SDK）→ V0.2
- ❌ Postgres / Redis 后端 → V0.2
- ❌ 人工审批 UI、横向对比趋势、统计检验

**判断新需求能否进 V0.1 的唯一标准**：不做它，"崩溃后不重做、副作用不重复"这条主链是否还能演示成立？不能才算必做。

## 3. V0.1 验收（可执行、可复现）

| # | 命令 | 通过标准 |
|---|---|---|
| A1 | `peracta run examples/refund_agent.py` | 正常跑完，退出码 0 |
| A2 | 手工 `kill -9` 后在执行中途，再 `peracta resume <run-id>` | 已完成的 step 不重跑、已提交的 effect 不重复执行 |
| A3 | `peracta verify examples/refund_agent.py --fault crash --at every-step --repeat 50` | 报告重复副作用 **0 次** |
| A4 | `peracta verify examples/broken_agent.py ...` | **必须报出**重复副作用（反例故意不保护；报不出来 = 验证器失败） |
| A5 | `peracta replay <run-id>` | 复现同一执行路径，输出与首次一致 |
| A6 | `pytest -q` / `ruff check .` | 全绿 |

**A4 是整份文档里最重要的一条。** 一个声称能发现问题的验证器，必须有一个"故意坏掉"的样例证明它真的会发现。

## 4. 已定决策

| 项 | 决定 | 理由 |
|---|---|---|
| 语言 | Python ≥ 3.13（`pyproject.toml` 已写） | 生态与自身熟悉度 |
| 运行时依赖 | **0 个** | 硬约束，也是分发卖点：装得上、审得过 |
| 存储 | SQLite（标准库 `sqlite3`） | 零依赖、单文件、可 `kill -9` 实测 |
| CLI | `argparse`（标准库） | 维持零依赖 |
| API 风格 | **同步优先**，async 延后 | 减少 V0.1 变量；内核逻辑与并发模型解耦 |
| License | **MIT** | 采用量优先 |
| 名字 | `peracta` / 毕录 | PyPI、npm 实测双空；无同领域产品冲突 |
| 工具链 | **uv**（环境/依赖）+ **ruff**（lint/format）+ pytest；Python **3.13** | 唯一入口；不引入 black/isort/flake8；门禁见 [AGENTS.md](../AGENTS.md) |

## 6. 差异化（一句话 + 对照）

> **Temporal / Restate 给你"不会重跑"；Peracta 给你"证明没有重复产生副作用"。**

| | Temporal / Restate | LangGraph / crewAI | actenon-scan | **Peracta** |
|---|---|---|---|---|
| 已完成步骤不重跑 | ✅ | 部分 | — | ✅ |
| 副作用恰好一次 | 需自行实现 | ❌（issue 在等） | — | ✅ |
| 确定性重放整次运行 | 仅 workflow code | ❌ | — | ✅ |
| 故障注入证明"没重复" | ❌ | ❌ | 静态扫描 | ✅ |
| 零运行时依赖 | ❌ | ❌ | ✅ | ✅ |

3. **决策记录两级制**：§9 记一行流水；被代码逼出的**重大**决策（存在被否的真实备选、事后难以逆转、一行装不下）另写 `docs/adr/NNNN-slug.md`，模板与判据见 [AGENTS.md](../AGENTS.md) §4.6；被取代标 superseded、不改写正文。**没有真实备选的琐事只配 §9 一行。**

## 8. 第一张任务卡（V0.1 五步）

> **可执行的实施计划在 `docs/plans/`（工作件，不占 §7 的"规格文档"名额）：**
> - [2026-10-06-v0.1-durable-core.md](plans/2026-10-06-v0.1-durable-core.md) —— **计划一**：T1–T3 持久化核心（6 张任务卡，含完整代码、测试与验收命令）
> - **计划二**（T4 副作用幂等 / T5 故障注入 / A5 重放）在计划一落地后另立
>
> **一处有意的偏离**：T2 原写"runs / events / claims 三张表"，计划一只建 `runs` + `events`
> —— `claims` 的字段由 T4 的预占状态机决定，提前建表只会返工（YAGNI）。
>
> 下表是任务卡**索引**；具体步骤、文件、接口与验收命令以计划文件为准。

| 卡 | 内容 | 验收命令 |
|---|---|---|
| **T1** | 骨架：补全 `pyproject.toml`、`src/peracta/`、pytest、ruff、CI | `python -c "import peracta"` + `pytest -q` + `ruff check .` |
| **T2** | SQLite 事件日志与 run 状态（runs / events / claims 三张表） | 单测：写入事件、按 run 读回、崩溃后仍能读到状态 |
| **T3** | `step` 录制 + `peracta resume` 跳过已完成步骤 | 5 步流程在第 3 步抛错，resume 后前 2 步的执行计数仍为 1 |
| **T4** | `effect` 幂等（先 claim 再执行）+ `reconcile` 未知态 | 集成测试：`kill -9` 后同一 effect 的副作用计数 = 1 |
| **T5** | `peracta verify` 故障注入 + 报告，并配一个**故意坏掉**的反例 | A3 报 0 次 且 A4 **必须**报出重复副作用 |

**每张卡做完就打 tag**（`v0.1.0-t1` … `v0.1.0-t5`），T5 完成即 V0.1 可用。
