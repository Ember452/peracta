## 1. 先说五个最深的扩展

如果只挑五个做，挑这五个 —— 它们各自都能撑起一篇技术分享。

### E-1 🟢 **确定性仿真测试引擎（DST）**

把真实时钟、随机源、IO、调度点全部虚拟化，让"崩溃"从**随机事件**变成**可枚举输入**。

- **深度**：要求内核所有非确定性来源都收敛到可注入接口；本质是把并发与故障变成种子（seed）。失败可 100% 复现，并可自动最小化种子。
- **验收设想**：给定种子必复现同一次崩溃；种子最小化能把 10 万事件的失败缩到 20 个事件以内。
- **参照**：FoundationDB / TigerBeetle / Antithesis 的路线。

### E-2 🟢 **账本协议的模型检验**

用 TLA+（或 Alloy）把预占状态机写成规格，用 TLC 穷举验证"至多一次执行"与"无孤儿预占"。

- **深度**：形式化建模 + 状态空间削减。能发现单元测试永远发现不了的边界（例如"补偿执行中途崩溃"的复合情形）。
- **验收设想**：故意在规格里注入 bug，TLC 必须报出；规格与实现对拍。

### E-3 🟢 **不可篡改的事件日志（哈希链）**

每条事件携带前序哈希，形成可校验的链；改一条历史事件必然被发现。

- **深度**：追加写下的链式校验、并发写入时的定序、批量校验性能；进一步可做 Merkle 树锚点，支持"某次副作用包含在某个历史状态"的包含证明。
- **验收设想**：手工篡改一条历史事件，校验器必须定位到该事件。

### E-4 🟡 **跨过程副作用静态分析**（借自 actenon-scan）

从入口（`@flow` / `@tool` / MCP 装饰器）沿调用图追到真实副作用 sink。

- **深度**：动态语言的解析不确定性必须被**显式建模**（见 C2 的边确定性三态）；效果摘要沿强连通分量迭代到不动点以处理递归。
- **验收设想**：一个 `@tool` 只调用 helper、helper 里 `requests.post` 的经典样例必须被抓到。

### E-5 🟡 **差分测试 / 语义一致性套件**

同一份工作流在两个引擎下运行（Peracta vs Temporal/其他），比较副作用序列与最终状态。

- **深度**：跨引擎语义对齐；差异必须分类为"真差异"与"实现细节差异"，否则报告没有说服力。
- **想象力**：这条让 Peracta 从"另一个运行时"变成"**所有运行时的公证人**"。

## 2. 主题 A：验证与证明

| ID | 功能 | 深度在哪 | 状态 |
|---|---|---|---|
| A1 | 线性一致性 / 历史检查器（Jepsen 风格） | 定义可机械检查的性质（每 key 至多一次 commit、无悬空 executing），实现 checker 而非靠人工 review | 🟢 |
| A2 | 覆盖引导的故障注入 | 用执行覆盖驱动注入点选择，把模糊测试的启发式搬到崩溃注入上；相同预算下覆盖率更高 | 🟢 |
| A3 | 性质测试（Hypothesis） | 写不变量而非用例；自动收缩出最小反例，覆盖预占/补偿/对账全路径 | 🟢 |
| A4 | **变异测试：验证验证器** | 往实现里注入变异（漏写预占、错序提交），检查 `verify` 能否发现 —— 回答"你的验证器真的有效吗" | 🟡 |
| A5 | 分布式故障注入编排 | 多进程/多机协同注入，模拟网络分区与节点失联（依赖集群化） | 🟡 |
| A6 | 可靠性基线与回归门禁 | PR 上比较的是"是否退化"而非"是否通过"；需要噪声地板与抽样策略 | 🟡 |
| A7 | 运行期廉价不变式断言 | 把关键不变式做成开发模式常开的断言，生产可抽样 | 🟡 |
| A8 | 不可检测边界的显式清单 | 维护"我们检测不到什么"的公开列表，并随版本更新 | 🟢 |

## 4. 主题 C：静态分析与规则

| ID | 功能 | 深度在哪 | 状态 |
|---|---|---|---|
| C1 | 仓库级跨过程分析 | 符号索引 + 调用图 + 从入口的传递可达性（含深度限制与显式披露） | 🟡 |
| C2 | **边确定性三态**（RESOLVED / HEURISTIC / UNRESOLVED） | 只有全 RESOLVED 的路径才产生发现，HEURISTIC 仅作证据记录 —— **绝不把"未知"悄悄当成"安全"** | 🟡 |
| C3 | 效果摘要 + SCC 不动点传播 | 每个函数算出"会触发的效果集合"，沿强连通分量迭代到不动点处理递归 | 🟡 |
| C4 | 内置效果大类（16 类）+ 30+ 守卫模式 | 支付 / 邮件 / 删除 / 部署 / 密钥 / 数据库写 / 仓库变更 / 浏览器动作…；识别既有的鉴权守卫名 | 🟡 |
| C5 | 自定义规则（配置驱动） | 用户注册自己的包装函数名与守卫名。**能加框架支持而不用等上游发版** | 🟡 |
| C6 | 抑制与基线 | 行内抑制 + 基线文件（只报新增）；**抑制本身要留痕**，否则等于永久静音 | 🟡 |
| C7 | 多语言 | 先 Python，再 TypeScript / Go；**不支持的语言必须显式报"未分析"，绝不静默当作干净** | 🔴 |
| C8 | 危险**结构**模式 | 不只是危险调用：识别"先扣款后校验""裸调用在重试循环里""无幂等键"等结构 | 🔴 |
| C9 | LSP / IDE 集成 | 把发现以诊断形式送进编辑器，写代码时即提示；增量分析性能与缓存失效是难点 | 🔴 |

## 10. 从 actenon-scan 借鉴的清单（对照）

> 它是我在这一类里见过的**工程完成度最高**的项目（零依赖、三语言、0.96 秒扫 1,954 文件、一整个生态）。
> 它的能力值得系统性地搬过来，尤其是最后三条。

| actenon-scan 的能力 | Peracta 里的对应形态 | 优先级 |
|---|---|---|
| 面向 Agent 的后果动作静态扫描（16 大类） | C1–C4 | 高 |
| 仓库级跨过程分析 + 边确定性三态 + SCC 不动点 | C1 / C2 / C3 | 高 |
| 30+ 中立守卫模式 + 自定义规则（配置驱动） | C4 / C5 | 高 |
| 基线 + 行内抑制 | C6 | 中 |
| 多格式输出（含 SARIF / 自包含 HTML） | G7 | 高 |
| GitHub Action + 粘性 PR 评论 + SARIF 上传 | G8 | 高 |
| pre-commit hook + `--changed-only` 毫秒级 | G8 | 中 |
| 退出码契约（且 CLI 与 Action 默认值**故意不同**并写明理由） | G5 | 高 |
| `explain`：展示被分析的执行路径 | H2 / B4 | 中 |
| `fix`：多种补救路线，且**不强制绑定自家方案** | H6 | 中 |
| `brief`：一页纸对外说明 | H5 | 低 |
| **Soundness Challenge：公开盲区 + 挑战计分板 + 响应承诺** | G2 | **最高** |
| **强制"本次不建立什么"段落** | G3 | **最高** |
| **机器可验证的声明 CI（零依赖 / 安装命令 / 生态表由 CI 核对）** | G1 | **最高** |
| 不支持的语言显式报告，绝不静默当作干净 | C7 / G3 | 高 |
| 自动调参的并行（≥8 核且 ≥250 文件才并行，5–7 核保守串行） | E-1 / G4 | 中 |
| 基准绑定真实仓库 + 结果等价性测试 | G4 | 中 |
| `doctor` / 插件生命周期自检 | B4 / G9 | 低 |
| 生态拆分（协议 / 内核 / 凭据 / 多语言 SDK） | D2 | 低 |

**为什么最后三条标"最高"**：它们不是功能，是**信任机制**。一个声称"能证明你没问题"的工具，如果把"我证明不了什么"公开写清楚，可信度会比多十个特性高一个量级。这与本项目承诺 0（只声明观测到的事实）是同一件事。
